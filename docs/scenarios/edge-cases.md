# 境界値・日付またぎ・例外ケースのテストシナリオ

## 1. 日付またぎ・深夜帯の操作
- [ ] **深夜帯（23:50等）での再計画要求**
  - 条件: 23:50に「今日の残りタスクをやり直したい」と相談する
  - 期待する挙動: わずか10分間で全タスクを実行するような無理な提案をせず、翌日以降への繰り越しや諦める提案を適切に行うこと。
- [ ] **日をまたぐ活動（00:30等）の「今日/昨日」判定**
  - 条件: 日付が変わった直後（0:30等）に就寝前で「今日の予定を直して」と入力する
  - 期待する挙動: ユーザーの生活リズム（まだ寝ていない＝前日の延長）を理解し、前日分の残タスクとして処理するか、明確に「今日（新日付）」の予定を指しているか正しく判別できること。

## 2. 他日（翌日以降）へのタスク溢れ・過積載
- [ ] **翌日の活動可能時間を超える繰り越し**
  - 条件: 今日溢れた3時間分のタスクを、すでに予定が満杯の明日に移動しようとする
  - 期待する挙動: 明日のスケジュールの空き容量を超過する場合、警告を出すか、さらに別日（明後日等）へ分散させる提案を行うこと。
- [ ] **遠い未来・締切ギリギリへの繰り越し**
  - 条件: 締切直前のタスクを翌日以降に押し出す
  - 期待する挙動: 締切（デッドライン）をオーバーしてしまう移動を自動で行わず、ユーザーに手動判断を仰ぐこと。

## 3. 画面数値計算（主な変更）とAI回答の整合性
- [ ] **UIの計算数値とAIチャットテキストの不一致防止**
  - 条件: `/replan` 画面の「主な変更」（例: 「今日の自由時間: +35分」）が表示される変更を行う
  - 期待する挙動: AIがチャット文章内で「自由時間が1時間増えます」のように画面の計算結果と食い違う発言をしないこと。

## 4. エラー・異常値入力への不具合防止
- [ ] **0分タスク・極端な長時間の変更要求**
  - 条件: 「このタスクを0分にして」「25時間作業する」等の不合理な入力
  - 期待する挙動: システムエラーを起こさず、適切なエラーメッセージまたは一般的な範囲（数分〜数時間）への自動補正を行うこと。
- [ ] **直前会話のコンテキスト消失・矛盾**
  - 条件: 3〜4回連続で「やっぱりA案で」「いやB案で」「それもやめて元に戻して」と変更を繰り返す
  - 期待する挙動: 文脈が混乱せず、最終的に指定された状態のスケジュールデータ（JSON等）を正しく出力できること。
