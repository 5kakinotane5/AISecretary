# /today 今日の調子（チェックイン）のテストシナリオ

## 1. 入力制限と表示切替
- [ ] **1日1回制限と固定表示**
  - 条件: 気分・疲労・集中の3択を選択して「決定」を押す
  - 期待する挙動: 入力フォームが消えて1行の表示（例: 「気分:普 / 疲労:高 / 集中:低」）に切り替わり、当日は再編集・再送信が不可能になる。
- [ ] **リロード・再起動後の状態保持**
  - 条件: チェックイン完了後にページをリロード、またはアプリを再起動する
  - 期待する挙動: 再び入力フォームが表示されることはなく、選択済みの1行表示が維持される。

## 2. 状態に応じた提案ボタンの出現と連携
- [ ] **体調不良・集中低下時の「AIに相談する」ボタン出現**
  - 条件: 疲労度「高」、気分「低」、集中「低」などの選択肢を選んで決定する
  - 期待する挙動: 1行表示の隣（または下）に「AIに相談する」ボタンが表示される。
- [ ] **絶好調時の前倒し提案導線**
  - 条件: 疲労「低」・集中「高」などの好調な選択肢を選んで決定する
  - 期待する挙動: 「調子が良さそうです！タスクを前倒ししますか？」などのポジティブな提案・相談導線が表示される。
- [ ] **選択値に応じた /replan へのコンテキスト引き継ぎ**
  - 条件: 選択した状態（疲労「高」、集中「低」、気分「最低」、絶好調など）で相談ボタンを押す
  - 期待する挙動: 選択理由に応じたメッセージ（例: 疲労高➔「今日は疲れた」、集中低➔「集中が続かない」、絶好調➔「調子がいいのでタスクを前倒ししたい」）が `/replan` 画面の初期メッセージとして渡される。

## 3. スケジュール影響とルール（FR-08-14）の検証
- [ ] **チェックイン単体での計画未変更（FR-08-14遵守）**
  - 条件: チェックイン（調子の入力）を完了する
  - 期待する挙動: チェックインを行っただけで、今日の予定やタスク時間・配置が勝手に自動更新されないこと。
- [ ] **「AIに相談する」経由での再計画**
  - 条件: ユーザーがボタンを押して `/replan` に移動し、会話を開始する
  - 期待する挙動: ユーザーが明示的に相談した場合のみ、AIから調子に応じたスケジュール再構成案が提示される。

## 4. 境界値・例外ケース
- [ ] **未入力のまま時間が経過した場合**
  - 条件: 朝チェックインせず、夕方〜夜になってから初めて調子を入力する
  - 期待する挙動: エラーにならず正常に登録され、残りの時間に応じた表示・相談導線が機能する。
- [ ] **日付またぎ（00:00）でのリセット**
  - 条件: チェックイン完了済みの状態で日付が変わる（例: 23:59 ➔ 00:01）
  - 期待する挙動: 新しい日のチェックイン入力フォームが再び表示され、入力可能状態に戻る。
