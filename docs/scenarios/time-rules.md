# 時間制約・余白・自由時間のテストシナリオ

## 1. UI表記統一とブロック結合ロジック
- [ ] **「自由時間」への表記統一と「ズレ備え時間」**
  - 条件: `/today`、`/plans`（比較表）、`/calendar`、設定画面を確認する
  - 期待する挙動: 「余白」という表記がすべて「自由時間」に統一され、設定画面では「予定のずれに備える時間（最低）」と表記されていること。
- [ ] **隣り合うブロックの統合と候補タスク保持**
  - 条件: スケジュール上で「余白」と「自由時間」が隣り合って配置される
  - 期待する挙動: 画面上で1つの「自由時間」ブロックとして結合して表示され、かつ「候補：メール返信」などのメタデータ（候補タスク）が消えずに保持されていること。

## 2. AI再計画時の時間ルール・制約遵守
- [ ] **「予定のずれに備える時間（最低）」の死守**
  - 条件: ユーザーが「今日の予定をギチギチに詰め込んで」「空き時間を全部タスクにして」と要求する
  - 期待する挙動: 設定されている最低限のズレ備え時間を無視せず、最低予備時間を確保した上で限界のスケジュールを提案する（または「これ以上詰め込めません」と回答する）。
- [ ] **移動時間の保護**
  - 条件: 場所の移動を伴うタスクが連続するスケジュールで再計画を行う
  - 期待する挙動: タスク間の移動時間（「よく行く場所」等の設定値）が削られて物理的に移動不可能になるスケジュールを作らないこと。
- [ ] **睡眠・不可動時間の保護**
  - 条件: 「自由時間を全部作業に回して」と要求する
  - 期待する挙動: 生活リズム（就寝時間・食事時間等）を破壊するような無理な割り振りを防ぐこと。

## 3. 境界値・割り込み時の時間ガード
- [ ] **細切れの固定予定による自由時間の分断**
  - 条件: 自由時間の中に細切れの固定予定（15分程度のミーティング等）が複数割り込む
  - 期待する挙動: 結合ロジックが誤作動せず、固定予定の前後で正しく自由時間ブロックが分割・計算されること。
