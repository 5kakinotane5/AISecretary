### 0.2 この設計書のゴール

モック（mock-spec.md の完了条件をすべて満たした状態）の上で、**モックAPIの中身を本物に差し替えて Demo Path を通す**。各担当（A：AI/Backend/DB、B：Planning Engine、C：Frontend）が、質問せずに実装・テストできる粒度まで決める。

### 17.2 実装中に決めてよいこと（設計書に追記しなくてよい）

- 設計書に名前がない内部の関数・変数・ファイル（`lib/server/repositories/` の中など）の名前と分け方
- `config.ts` の数値の調整（10.14・12.7 のテストが通る範囲で。変えたら PR に書く）
- design-spec に沿った、画面の細かな文言・余白
- ログの形式

これ以外（API の形、スキーマ、DB の列、状態遷移、配置のルール、画面の動き）を変える必要が出たら、設計書に追記してから実装する。

### 17.3 時間が余ったらやること（Demo Path が通った後）

優先順：① タスクの登録・編集画面（`/settings` に「タスク」欄。API は 9.2）、② チェックインの入力（`/today` の上部に気分・疲労・集中の3択）、③ `/settings` のログアウトボタン、④ ヒアリングの会話の復元。

### 17.4 既知の制約（デモで説明できるようにしておく）

- 計画は「今週」だけ。翌週はヒアリングからやり直す
- 月曜は昼食後すぐ帰宅するため、大学（図書館）での作業は入らない（モックとの違い）
- 就寝前30分（23:30〜24:00）は自由時間で、タスクは入らない
- 毎週の予定は、登録した週より前の週にも表示される
- 再計画は今日の分だけ。「今から30分だけ何かやりたい」などの希望は未対応
- 18:00 の「今日は疲れた」で変わるのは、夜の目標タスク（TOEIC）だけ。ES は午後に終わっているため移らない（mock-spec 5.10 との違い）
- 3案の中身は探索の結果で決まるため、モック（mock-spec 5.9）と同じ配置にはならない。デモの前提（月曜 18:00 以降に TOEIC がある）は P14のテストで確かめる
- 生成は探索のため、デモの入力で3秒以内を目標にする。超えた場合は P13の順で `config.ts` を調整する

## 18. 将来の拡張（MVP 後）

数学モデルの大部分は v1.3 で MVP に入った（付録P）。MVP 後に残すもの：

| 項目 | MVP | 拡張時 |
|---|---|---|
| 長期の希望からの学習（「今後は朝に勉強したい」、η ≈ 0.15） | 扱わない | 自然言語から時間帯・重みの変更を取り出し、`preference_weights` と目標の時間帯を更新する（数学モデル 13.3） |
| 再計画の探索 | ルール（12.4） | 今日の now 以降を、変更の少なさを目的に加えたビーム探索で作り直す |
| 状態の変数 | 疲労・集中だけ | Mood・Motivation・AvailableEnergy をチェックインで取り、Fit と方向の調整に使う（数学モデル 3.1・12章） |
| 探索の範囲 | 今週だけ | 翌週以降も含めて割り振る（翌週の計画の自動作成） |

そのほか：週間・月間レビュー、Google Calendar 連携、自然言語によるタスク登録、地図 API による移動時間、移動中の軽作業（要件定義 12章）。
