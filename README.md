# パーソナルAI秘書 V0.1 要件定義書

## 1. プロジェクト概要

### 1.1 プロジェクト名
パーソナルAI秘書（Personal AI Secretary）

### 1.2 背景・理念
自己管理能力や計画力が十分でないことによって、本来得られるはずだった機会を逃してしまう人がいる。

しかし、本人が「改善したい」と自覚していても、予定管理・タスク整理・優先順位付け・計画立案そのものが負担となり、継続的な自己管理が難しい場合がある。

本プロジェクトでは、人間自身を無理に変えるのではなく、AIが自己管理に伴う認知的負荷を引き受けることで、この問題を解決する。

AIは単なるタスク管理ツールではなく、「自分の生活を一緒に整理してくれる秘書」として機能する。

### 1.3 プロダクトの基本理念
- ユーザーの自己管理に必要な認知負荷をAIが引き受ける
- 「何をすべきか」だけでなく「今日はどうしたいか」を尊重する
- AIが一方的に予定を押し付けるのではなく、ユーザーと相談しながら計画を作る
- 予定を登録する面倒と、予定を決める面倒を区別する
- 締切のあるタスクと、締切のないタスクを区別する
- 日々の生活に十分なバッファを確保する
- 月次・週次の対話によって長期的な方向性を整理する
- 完璧な効率化ではなく、継続可能な生活を目指す

---

# 2. 解決する課題

## 2.1 予定管理の負担

ユーザーは、
- 大学の予定
- バイト
- 就活
- 私生活
など複数の予定を管理する必要がある。

予定を一つずつ登録・整理すること自体が負担になる。

## 2.2 今日やることを決める負担

予定やタスクが分かっていても、

- 今日は何をやるべきか
- どの順番でやるか
- どこまでやればよいか
- 今日は休むべきか

を毎日考える必要がある。

この「計画を決める作業」自体をAIに委任する。

## 2.3 締切のないタスクの扱い

TOEIC、ケース面接対策、企業研究などは、明確な締切が存在しない場合がある。

しかし「やらなくても今日の生活は成立する」一方で、「やった方が将来的な利益が大きい」。

したがって、単純な締切順ではなく、将来価値・継続状況・ユーザーの方針などを考慮して計画する必要がある。

## 2.4 ユーザーの気分・状態を無視した最適化

単純な生産性最大化では、毎日予定を詰め込むことになり、継続性が失われる可能性がある。

そのため、AIは毎日の状態を確認し、

「今日は頑張りたい」
「今日はゆっくりしたい」
「夜は空けたい」

などの意思を計画に反映する。

## 2.5 長期的な方向性が曖昧になる問題

日々のタスクだけを処理していると、「そもそも何を目指しているのか」が曖昧になる。

そのため、
- 月次面談：抽象的な方向性から具体的な目標・方針へ落とし込む
- 週次面談：大枠を維持しながら細部を修正する

という仕組みを設ける。

# 3. プロダクトコンセプト

## 3.1 コンセプト

> 「自分を変える」のではなく、「自分を管理する負担をAIに任せる」。

AI秘書は、ユーザーの予定・タスク・目標・気分・生活上の制約を把握し、その日の状況に応じて実行可能な計画を提案する。

## 3.2 AIの役割

AIは以下を担当する。

1. 情報を受け取る
2. 情報を整理する
3. 優先順位を判断する
4. 今日の計画を作る
5. 必要に応じて再計画する
6. 判断理由を説明する
7. 長期的な方向性を定期的に確認する

AIはユーザーの意思決定を完全に奪うのではなく、意思決定に必要な負担を減らす。

---

# 4. 対象ユーザー

主な対象は以下のようなユーザー。

- 自己管理が苦手な学生
- 予定やタスクが多く整理が苦手な人
- 就活・大学・アルバイトなど複数の活動を並行している人
- 「何をすべきか」は分かっているが、計画を立てるのが面倒な人
- 将来のためのタスクを後回しにしやすい人
- 自分の気分や生活の余裕も大切にしたい人

---

# 5. 機能要件

## 5.1 日次チェックイン

ユーザーがその日の状態・希望を自然言語で入力できる。

### 入力例
- 「今日はゆっくりしたい」
- 「今日は就活を進めたい」
- 「夜は何もしたくない」
- 「今日はかなり集中できそう」
- 「ESだけは終わらせたい」

### AIが抽出する情報
- 活動意欲
- 自由時間への優先度
- バッファへの優先度
- 特定カテゴリへの優先度変更
- 希望する自由時間帯
- その他の計画上重要な条件

生のユーザー発言も保存する。

---

## 5.2 タスク登録

自然言語からタスクを登録できる。

### 例

「金曜までにA社のESを出したい。2時間くらいかかる」

↓

- タイトル：A社 ES
- 種類：締切あり
- 締切：金曜
- 必要時間：約120分
- 分割可能性：AIが推定

不足情報だけAIが追加で質問する。

---

# 6. タスク分類

タスクは大きく2種類に分類する。

## 6.1 締切ありタスク

例：
- 大学の課題
- ES
- レポート
- 提出物

特徴：
- 明確な締切がある
- 締切から逆算して必要な作業量を計算する
- 今日やる必要があるかを判定する

## 6.2 締切なしタスク

例：
- TOEIC勉強
- ケース面接対策
- 面接前の企業研究
- 読書
- スキル学習

特徴：
- やらなくても直近の予定には直接影響しない場合がある
- しかし将来的な利益がある
- 継続頻度や目標、現在の進捗などを考慮する

---

# 7. 今日の計画生成

AIは以下の情報を統合して1日の計画を生成する。

### 入力
- 固定予定
- タスク
- タスクの締切
- 必要作業時間
- ユーザーの今日の気分
- ユーザーの長期方針
- 睡眠時間
- バッファ設定
- 空き時間
- 過去の実績

### 出力
- 今日やるべきタスク
- タスクごとの時間
- 実行順序
- バッファ
- 自由時間
- 今日やらないタスク
- 判断理由

---

# 8. 優先度カテゴリ

タスクは以下の4種類に分類する。

### MUST
今日やる必要性が高い。

### SHOULD
今日できれば進めたい。

### COULD
余裕があれば行う。

### NOT_TODAY
今日は行わない。

重要なのは「すべてのタスクを予定に入れる」のではなく、NOT_TODAYを明示することである。

---

# 9. バッファ要件

AIは空き時間をすべてタスクで埋めてはいけない。

最低限のバッファ時間を確保する。

バッファには以下を含む。

- 予定変更への対応
- 移動
- 休憩
- 想定外の作業
- 自由時間
- 疲労回復

ユーザーが希望するバッファ量を設定できる。

---

# 10. 計画の再生成

日中に予定や気分が変わった場合、計画を再生成できる。

### 例

ユーザー：
「今日は疲れた」

AI：
- MUSTだけ残す
- SHOULDを削減
- COULDを削除
- バッファを増加

ユーザー：
「18時から友達と食事になった」

AI：
- 18時以降を空ける
- 必要なタスクを前倒し
- 不要なタスクを翌日以降へ移動

再計画時も、ユーザーに変更内容と理由を提示する。

---

# 11. 月次面談

月1回、固定された時間を確保して実施する。

目的は、

> 抽象的な方向性 → 具体的な目標・方針

への落とし込み。

質問は固定的なアンケートではなく、会話内容に応じて柔軟に変化する。

### 基本テーマ
- 今何を目指したいのか
- なぜそれを目指すのか
- その「どんな」を具体化するとどうなるか
- 何を優先するのか
- 今月どこまで進めたいのか
- 現在の方針を変える必要があるか

---

# 12. 週次面談

週1回、固定された時間を確保して実施する。

目的は、月次で決めた大枠を維持しながら細部を修正すること。

### 確認項目
- 先週の進捗
- 計画と実績の差
- 今週の優先事項
- 方針に対する違和感
- タスク量の調整
- 翌週への修正

---

# 13. 計画モード

初期段階ではAIが詳細な計画を作成する。

ユーザーがサービスに慣れてきたら、AIは前回の方針を前提に微調整する。

ただし、大きな方針転換があった場合は再び詳細な計画を作成する。

### 状態

- `INITIAL_PLANNING`
- `MAINTENANCE`
- `REPLANNING`

---

# 14. カレンダー連携

Google Calendar等と連携し、固定予定を取得する。

AIが作成した予定は、原則としてユーザー確認後にカレンダーへ反映する。

AIが勝手に重要な予定を削除・変更しない。

---

# 15. AI秘書チャット

ユーザーは自然言語でAIに指示できる。

例：
- 「今日疲れた」
- 「予定変わった」
- 「明日までにES追加」
- 「20時以降は空けたい」
- 「今週はTOEICを頑張りたい」

AIは単なる回答ではなく、必要に応じて以下を更新する。

- タスク
- チェックイン
- 計画
- カレンダー反映候補

---

# 16. 非機能要件

## 16.1 使いやすさ

ユーザーが細かいフォームを大量に入力しなくても使えること。

## 16.2 説明可能性

AIがなぜその計画を作ったのか説明できること。

例：

> 「ESは締切までの残り時間を考えると今日90分進める必要があるためMUSTにしました。」

## 16.3 可逆性

AIが提案した計画は、ユーザーが簡単に変更・拒否できること。

## 16.4 安全性

AIが以下を無視して効率化を優先しない。

- 睡眠
- 固定予定
- 最低限の休憩
- ユーザーが指定した自由時間
- 最低バッファ

# 19. プロダクトの最重要原則

本プロジェクトでは、以下を最重要原則とする。

> **AIはユーザーの生活を最大限効率化することを目的としない。**
>
> **ユーザーがその日に望む生活を尊重しながら、必要なことを可能な限り少ない認知負荷で実行できるようにする。**

したがって、

「空いている時間があるからタスクを入れる」

ではなく、

「今日のユーザーの状態・長期方針・締切・将来価値・生活上の余裕を考慮した結果、その時間をどう使うのが妥当か」

を判断するシステムとする。
